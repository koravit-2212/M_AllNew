# Feature: จัดการข้อมูลระบบ (System Data Management)
Spec ID: SPEC-SYS-001 | Source: Use Case Specification ระบบห้องสมุด, UC-13 | Use case: UC-13
Owner: TBD | Status: Draft v1 | Updated: 2569-09-19

## Goal
เจ้าหน้าที่ห้องสมุดที่มีสิทธิ์เพิ่ม แก้ไข ลบ และค้นหาข้อมูลหนังสือ ข้อมูลบริการ และข้อมูลการใช้บริการ
ผ่านเมนูจัดการข้อมูลระบบเดียว โดยทุกการดำเนินการถูกตรวจสอบความถูกต้องและบันทึก Audit Log
เพื่อให้ข้อมูลในระบบถูกต้องและเป็นปัจจุบันตลอดเวลา

## Scope
### In scope
- เมนูกลางสำหรับเลือกประเภทข้อมูล (หนังสือ/บริการ/การใช้บริการ) และดำเนินการ เพิ่ม/แก้ไข/ลบ/ค้นหา
- ตรวจสอบสิทธิ์เจ้าหน้าที่ก่อนเข้าถึง และตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก พร้อม Audit Log
### Out of scope
- หน้าจอ/ฟลว์เฉพาะของการจัดการข้อมูลหนังสือ/บริการโดยละเอียด (UC-11) และข้อมูลผู้ใช้บริการโดยละเอียด (UC-10)
  — UC-13 เป็นเมนูกลางที่ครอบคลุมภาพรวม ส่วน UC-10/UC-11 ลงรายละเอียดเฉพาะทาง

## Constraints
- DOM-PRV-01 การจัดเก็บและใช้งานข้อมูลส่วนบุคคลต้องเป็นไปตามนโยบายมหาวิทยาลัยและกฎหมาย (BR-PRV-01)
- CON-AUDIT-01 ทุกการกระทำที่สำคัญของเจ้าหน้าที่ต้องถูกบันทึกลง Audit Log (NFR-SEC-02)
- CON-SEC-01 ทุกการเชื่อมต่อต้องใช้ HTTPS (NFR-SEC-03)

## Requirements
- FR-SYS-01 ระบบต้องตรวจสอบสิทธิ์ของเจ้าหน้าที่ก่อนเข้าเมนู "จัดการข้อมูลระบบ"                     <- UC-13 ขั้น 1-2
- FR-SYS-02 ระบบต้องแสดงประเภทข้อมูลที่สามารถจัดการได้ (หนังสือ/บริการ/การใช้บริการ) ให้เลือก        <- UC-13 ขั้น 3-6
- FR-SYS-03 ระบบต้องให้เจ้าหน้าที่ เพิ่ม/แก้ไข/ลบ/ค้นหา ข้อมูลตามประเภทที่เลือก                     <- UC-13 ขั้น 7-8
- FR-SYS-04 ระบบต้องตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก และบันทึกลงฐานข้อมูลพร้อม Audit Log เมื่อผ่าน  <- UC-13 ขั้น 9-11
- FR-SYS-05 เมื่อเจ้าหน้าที่ไม่มีสิทธิ์เข้าใช้เมนูนี้ ระบบต้องปฏิเสธการเข้าถึงและแจ้งเตือน             <- UC-13 exception 2a
- FR-SYS-06 เมื่อข้อมูลไม่ผ่านการตรวจสอบความถูกต้อง ระบบต้องแจ้งข้อผิดพลาดและไม่บันทึกข้อมูล        <- UC-13 exception 9a

## Quality Requirements
- NFR-SEC-01 ระบบต้องมีการรักษาความปลอดภัยของข้อมูลส่วนบุคคลของนักศึกษา
- NFR-SEC-02 ระบบต้องมีการบันทึก Audit Log สำหรับการกระทำที่สำคัญของ Admin/เจ้าหน้าที่
- NFR-SEC-03 ระบบต้องใช้การเชื่อมต่อที่ปลอดภัย เช่น HTTPS

## Acceptance Criteria
- [ ] AC-SYS-01 (FR-SYS-01, FR-SYS-04)
      Given เจ้าหน้าที่มีสิทธิ์จัดการข้อมูลระบบและข้อมูลที่กรอกถูกต้อง
      When  เจ้าหน้าที่กดยืนยันการดำเนินการ
      Then  ระบบบันทึกข้อมูลลงฐานข้อมูลและแสดงข้อความ "ดำเนินการสำเร็จ" พร้อมมี Audit Log
- [ ] AC-SYS-02 (FR-SYS-03, FR-SYS-06)
      Given ข้อมูลที่เจ้าหน้าที่กรอกไม่ถูกต้อง
      When  เจ้าหน้าที่กดยืนยันการดำเนินการ
      Then  ระบบแจ้งข้อผิดพลาดและไม่บันทึกข้อมูล
- [ ] AC-SYS-03 (FR-SYS-01, FR-SYS-05)
      Given เจ้าหน้าที่ไม่มีสิทธิ์เข้าใช้เมนูจัดการข้อมูลระบบ
      When  เจ้าหน้าที่พยายามเข้าเมนู
      Then  ระบบปฏิเสธการเข้าถึงและแจ้งเตือน
- [ ] AC-SYS-04 (FR-SYS-02)
      Given เจ้าหน้าที่เข้าเมนู "จัดการข้อมูลระบบ" สำเร็จ
      When  เจ้าหน้าที่ดูรายการประเภทข้อมูลที่จัดการได้
      Then  ระบบแสดงประเภทข้อมูลหนังสือ ข้อมูลบริการ และข้อมูลการใช้บริการให้เลือกครบถ้วน

## Assumptions & Open Questions
- ASM-01 UC-13 เป็นเมนูกลาง (dashboard) ที่เชื่อมโยงไปยังฟังก์ชันเดียวกับ UC-10/UC-11 มากกว่าเป็นระบบแยกต่างหาก
- Q-01 UC-13 ทับซ้อนกับ UC-10 (จัดการข้อมูลผู้ใช้บริการ) และ UC-11 (จัดการข้อมูลหนังสือ/บริการ) หรือไม่ ควรรวมเป็น Use Case เดียวหรือแยกตามสิทธิ์การเข้าถึง? -> ถามทีมวิเคราะห์ระบบ/ห้องสมุด
- Q-02 "ข้อมูลการใช้บริการ" ในขั้น 4 หมายถึงข้อมูลเชิงสถิติ/รายงาน (เชื่อมกับ FR-RPT-01 ที่ยังไม่มี Use Case รองรับ) หรือหมายถึงประวัติรายการเข้าใช้บริการดิบ? -> ถามห้องสมุด
