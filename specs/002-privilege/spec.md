# Feature: ตรวจสอบสิทธิ์การเข้าใช้บริการ (Access Verification)
Spec ID: SPEC-AVR-001 | Source: Use Case Specification ระบบห้องสมุด, UC-02 | Use case: UC-02
Owner: TBD | Status: Draft v2 | Updated: 2569-09-20

## Goal
เมื่อระบบหลัก (UC-01) ส่งข้อมูลบัตรนักศึกษามา ระบบต้องตรวจสอบกับระบบบัตรนักศึกษาและตอบผลสถานะสิทธิ์
กลับไปอย่างรวดเร็วและแม่นยำ เพื่อให้ UC-01 ตัดสินใจอนุญาต/ปฏิเสธการเข้าใช้บริการได้ถูกต้อง

## Scope
### In scope
- รับข้อมูลนักศึกษาจาก UC-01 และส่งต่อไปตรวจสอบกับระบบบัตรนักศึกษาภายนอก
- ตรวจสอบสถานะของนักศึกษา (ปกติ/ถูกระงับสิทธิ์/ไม่พบข้อมูล) และส่งผลกลับ
### Out of scope
- การอ่าน QR Code/บัตรที่จุดเข้า และการบันทึกประวัติการเข้าใช้บริการ (UC-01)
- การจัดการสิทธิ์ผู้ใช้บริการ (UC-10)

## Constraints
- IF-STD-01 ต้องเรียกใช้ระบบบัตรนักศึกษา (ภายนอก) ผ่านการเชื่อมต่อที่กำหนดโดยฝ่าย IT
- CON-ELG-01 ผู้ใช้บริการต้องเป็นนักศึกษา บุคลากร หรือผู้ที่ได้รับอนุญาต (BR-ELG-01)
- CON-IDN-01 การตรวจสอบต้องอ้างอิงบัตรนักศึกษาหรือ QR Code ที่ตรวจสอบตัวตนได้ (BR-IDN-01)
- CON-SEC-01 ทุกการเชื่อมต่อต้องใช้ HTTPS (NFR-SEC-03, system-wide)

## Requirements
- FR-AVR-01 ระบบต้องรับข้อมูลนักศึกษาและส่งไปตรวจสอบกับระบบบัตรนักศึกษา                          <- UC-02 ขั้น 1-2
- FR-AVR-02 ระบบต้องตรวจสอบสถานะของนักศึกษาจากผลที่ระบบบัตรนักศึกษาส่งกลับ และแสดงผลการตรวจสอบตามสถานะหลักที่กำหนดไว้ 3 สถานะคือ ปกติ/ถูกระงับสิทธิ์/ไม่พบข้อมูล โดยข้อความที่แสดงต้องสั้น กระชับ และสื่อความหมายตรงกับสถานะ  <- UC-02 ขั้น 3-5
- FR-AVR-03 เมื่อระบบบัตรนักศึกษาขัดข้องหรือไม่ตอบสนองภายใน 5 วินาที ระบบต้องแจ้งให้ผู้ใช้ลองใหม่ภายหลัง และถือว่าการตรวจสอบล้มเหลว <- UC-02 exception 2a
- FR-AVR-04 เมื่อไม่พบข้อมูลนักศึกษาในระบบบัตรนักศึกษา ระบบต้องแสดงข้อความ “ไม่พบข้อมูลผู้ใช้” และไม่อนุญาตให้เข้าใช้บริการโดยอัตโนมัติ หากต้องการให้เจ้าหน้าที่ตรวจสอบต่อ ให้ใช้กระบวนการ Manual Verification เป็นขั้นตอนแยกต่างหาก <- UC-02 exception 4a

## Quality Requirements
- NFR-PRF-02 ระบบต้องตอบสนองการสแกนบัตรนักศึกษาได้อย่างรวดเร็ว โดยการเรียกระบบบัตรนักศึกษาต้องไม่เกิน 5 วินาที
- NFR-QAL-01 ระบบต้องมีความถูกต้องและแม่นยำในการตรวจสอบ QR Code
- NFR-SEC-01 ระบบต้องมีการรักษาความปลอดภัยของข้อมูลส่วนบุคคลของนักศึกษา

## Acceptance Criteria
- [ ] AC-AVR-01 (FR-AVR-01, FR-AVR-02)
      Given ระบบได้รับข้อมูลนักศึกษาที่ถูกต้อง
      When  ระบบส่งข้อมูลไปตรวจสอบกับระบบบัตรนักศึกษา
      Then  ระบบแสดงผลตามสถานะสิทธิ์การเข้าใช้บริการที่ถูกต้อง เช่น “ยืนยันสิทธิ์สำเร็จ”, “สิทธิ์ถูกระงับ”, หรือ “ไม่พบข้อมูลผู้ใช้”
- [ ] AC-AVR-02 (FR-AVR-03)
      Given ระบบบัตรนักศึกษาขัดข้องหรือไม่ตอบสนองภายใน 5 วินาที
      When  ระบบพยายามตรวจสอบสิทธิ์นักศึกษา
      Then  ระบบแจ้งให้ผู้ใช้ลองใหม่ภายหลัง และถือว่าการตรวจสอบล้มเหลว
- [ ] AC-AVR-03 (FR-AVR-04)
      Given ไม่พบข้อมูลนักศึกษาในระบบบัตรนักศึกษา
      When  ระบบตรวจสอบสถานะ
      Then  ระบบแสดงข้อความ “ไม่พบข้อมูลผู้ใช้” และไม่อนุญาตให้เข้าใช้บริการโดยอัตโนมัติ

## Assumptions & Open Questions
- ASM-01 ระบบบัตรนักศึกษาให้บริการ API แบบ synchronous ที่มี timeout ชัดเจน
- ASM-02 ผลการตรวจสอบสิทธิ์มี 3 สถานะหลักคือ ปกติ, ถูกระงับสิทธิ์, และไม่พบข้อมูล โดยข้อความที่แสดงต้องสั้น กระชับ และสื่อความหมายตรงกับสถานะ เช่น “ยืนยันสิทธิ์สำเร็จ”, “สิทธิ์ถูกระงับ”, “ไม่พบข้อมูลผู้ใช้”
- ASM-03 การเรียกระบบบัตรนักศึกษาจะมี timeout ไม่เกิน 5 วินาที หากเกินเวลาที่กำหนดให้ถือว่าการตรวจสอบล้มเหลวและดำเนินการตาม FR-AVR-03
- ASM-04 “ผู้ที่ได้รับอนุญาต” หมายถึง นักศึกษา บุคลากร หรือบุคคลที่ห้องสมุด/มหาวิทยาลัยกำหนดให้สามารถใช้บริการได้ โดยตรวจสอบสิทธิ์จากข้อมูลในระบบที่ห้องสมุดกำหนด เช่น ระบบบัตรนักศึกษา/ฐานข้อมูลสมาชิก
- ASM-05 หากไม่พบข้อมูลนักศึกษา ระบบจะแสดงข้อความ “ไม่พบข้อมูลผู้ใช้” และไม่อนุญาตให้เข้าใช้บริการโดยอัตโนมัติ หากต้องการให้เจ้าหน้าที่ตรวจสอบต่อ ให้ใช้ Manual Verification เป็นกระบวนการแยกต่างหาก
- ASM-06 Manual Override เฉพาะเจ้าหน้าที่ที่ได้รับสิทธิ์เท่านั้น และต้องบันทึกผู้ดำเนินการ วันเวลา เหตุผล และผลการยืนยันลง Audit Log
