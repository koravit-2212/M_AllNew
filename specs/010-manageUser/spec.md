# Feature: จัดการข้อมูลผู้ใช้บริการ (User Management)
Spec ID: SPEC-USM-001 | Source: Use Case Specification ระบบห้องสมุด, UC-10 | Use case: UC-10
Owner: TBD | Status: Draft v1 | Updated: 2569-09-19

## Goal
เจ้าหน้าที่ที่มีสิทธิ์ค้นหา ตรวจสอบ และแก้ไขข้อมูลผู้ใช้บริการ รวมถึงประวัติการเข้าใช้บริการและการยืม-คืน
โดยทุกการเปลี่ยนแปลงถูกบันทึกลง Audit Log เพื่อให้ข้อมูลผู้ใช้บริการถูกต้องและเป็นปัจจุบัน

## Scope
### In scope
- ตรวจสอบสิทธิ์เจ้าหน้าที่ก่อนเข้าถึงเมนู
- ค้นหาข้อมูลผู้ใช้บริการ และตรวจสอบข้อมูลการเข้าใช้บริการ/การยืม-คืนของผู้ใช้แต่ละคน
- เพิ่ม/แก้ไขข้อมูลผู้ใช้บริการ พร้อมบันทึก Audit Log
### Out of scope
- การจัดการข้อมูลหนังสือ/บริการ (UC-11) และข้อมูลระบบอื่น ๆ (UC-13)
- การกำหนดสิทธิ์การใช้งานของเจ้าหน้าที่เอง (FR-USR-01 - ยังไม่มี Use Case รองรับ)

## Constraints
- DOM-PRV-01 การเก็บและใช้งานข้อมูลส่วนบุคคลต้องเป็นไปตามนโยบายของมหาวิทยาลัยและกฎหมายที่เกี่ยวข้อง (BR-PRV-01)
- CON-SEC-01 ทุกการเชื่อมต่อต้องใช้ HTTPS (NFR-SEC-03)
- CON-AUDIT-01 ทุกการกระทำที่สำคัญของเจ้าหน้าที่/Admin ต้องถูกบันทึกลง Audit Log (NFR-SEC-02)

## Requirements
- FR-USM-01 ระบบต้องตรวจสอบสิทธิ์ของเจ้าหน้าที่ก่อนเข้าถึงเมนูจัดการข้อมูลผู้ใช้บริการ         <- UC-10 ขั้น 1-2
- FR-USM-02 ระบบต้องให้เจ้าหน้าที่ค้นหาข้อมูลผู้ใช้ หรือตรวจสอบข้อมูลการเข้าใช้บริการและการยืม-คืน  <- UC-10 ขั้น 3-4
- FR-USM-03 เมื่อเจ้าหน้าที่เพิ่ม/แก้ไขข้อมูล ระบบต้องบันทึกข้อมูลพร้อมบันทึก Audit Log         <- UC-10 ขั้น 5-6
- FR-USM-04 เมื่อเจ้าหน้าที่ไม่มีสิทธิ์จัดการข้อมูล ระบบต้องปฏิเสธการเข้าถึงและแจ้งเตือน           <- UC-10 exception 2a

## Quality Requirements
- NFR-SEC-01 ระบบต้องมีการรักษาความปลอดภัยของข้อมูลส่วนบุคคลของนักศึกษา
- NFR-SEC-02 ระบบต้องมีการบันทึก Audit Log สำหรับการกระทำที่สำคัญของ Admin/เจ้าหน้าที่
- NFR-SEC-03 ระบบต้องใช้การเชื่อมต่อที่ปลอดภัย เช่น HTTPS

## Acceptance Criteria
- [ ] AC-USM-01 (FR-USM-01, FR-USM-03)
      Given เจ้าหน้าที่มีสิทธิ์จัดการข้อมูล
      When  เจ้าหน้าที่แก้ไขข้อมูลผู้ใช้บริการ
      Then  ระบบบันทึกข้อมูลที่แก้ไข ปรับปรุงฐานข้อมูล และมีบันทึก Audit Log
- [ ] AC-USM-02 (FR-USM-01, FR-USM-04)
      Given เจ้าหน้าที่ไม่มีสิทธิ์จัดการข้อมูล
      When  เจ้าหน้าที่พยายามแก้ไขข้อมูล
      Then  ระบบปฏิเสธการเข้าถึงและแจ้งเตือน
- [ ] AC-USM-03 (FR-USM-02)
      Given เจ้าหน้าที่มีสิทธิ์และต้องการตรวจสอบผู้ใช้บริการรายหนึ่ง
      When  เจ้าหน้าที่ค้นหาด้วยรหัสนักศึกษาหรือชื่อ
      Then  ระบบแสดงข้อมูลผู้ใช้บริการ พร้อมประวัติการเข้าใช้บริการและการยืม-คืนที่ถูกต้อง
- [ ] AC-USM-04 (DOM-PRV-01, CON-AUDIT-01)
      Given มีการเปิดดูหรือแก้ไขข้อมูลส่วนบุคคลของผู้ใช้บริการ
      When  การดำเนินการเสร็จสิ้น
      Then  มี Audit Log ที่ระบุผู้เข้าถึง เวลา และรายการที่เปลี่ยนแปลง

## Assumptions & Open Questions
- ASM-01 สิทธิ์ในการจัดการข้อมูลผู้ใช้บริการกำหนดตามบทบาท (Role) ของเจ้าหน้าที่แต่ละคน
- Q-01 ระดับสิทธิ์ของเจ้าหน้าที่ (ดู/แก้ไข/ลบ) แบ่งอย่างไร และใครเป็นผู้กำหนด? -> เชื่อมโยงกับ FR-USR-01 ที่ยังไม่มี Use Case รองรับ - ถามห้องสมุด/ฝ่าย IT
- Q-02 Audit Log ต้องเก็บนานเท่าใด และใครเป็นผู้มีสิทธิ์ตรวจสอบย้อนหลัง? -> ถามฝ่าย IT/ผู้ดูแลด้าน PDPA ของมหาวิทยาลัย
