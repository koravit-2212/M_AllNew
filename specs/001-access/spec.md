# Feature: เข้าใช้บริการห้องสมุด (Access)
Spec ID: SPEC-ACC-001 | Source: Use Case Specification ระบบห้องสมุด, UC-01 | Use case: UC-01
Owner: TBD | Status: Draft v2 | Updated: 2569-09-19

## Goal
ผู้มีสิทธิ์ (นักศึกษา บุคลากร หรือผู้ที่ได้รับอนุญาตจากมหาวิทยาลัยหรือห้องสมุด) แสดงบัตรนักศึกษาหรือ QR Code ที่ประตูทางเข้า
แล้วเข้าห้องสมุดได้ทันทีเมื่อยืนยันตัวตนสำเร็จ โดยระบบบันทึกการเข้าใช้บริการและปรับสถานะ
การเข้าใช้บริการแบบ Real-time เพื่อให้ห้องสมุดควบคุมการเข้าใช้บริการได้อย่างปลอดภัยและถูกต้อง

## Scope
### In scope
- อ่านข้อมูลจากบัตรนักศึกษา/QR Code ที่จุดเข้า
- ตรวจสอบข้อมูลกับระบบบัตรนักศึกษา และตรวจสอบสิทธิ์การเข้าใช้บริการ
- บันทึกประวัติการเข้าใช้บริการ และปรับสถานะจำนวนผู้ใช้บริการปัจจุบันแบบ Real-time
### Out of scope
- การตรวจสอบสิทธิ์เชิงลึก/การเรียก API ของระบบบัตรนักศึกษา (แยกไว้ที่ UC-02)
- การจัดการข้อมูลผู้ใช้บริการ เช่น เพิ่ม/แก้ไขสิทธิ์ (UC-10)

## Constraints
- IF-STD-01 ต้องเชื่อมต่อกับระบบบัตรนักศึกษาภายนอกเพื่อตรวจสอบข้อมูล (ดู UC-02)
- IF-STD-02 เมื่อระบบบัตรนักศึกษาภายนอกไม่สามารถตรวจสอบข้อมูลได้หรือไม่ตอบกลับ ระบบต้องไม่อนุญาตให้เข้าและแจ้งให้ผู้ใช้ลองใหม่หรือติดต่อเจ้าหน้าที่
- DOM-PRV-01 การเก็บและใช้งานข้อมูลส่วนบุคคลต้องเป็นไปตามนโยบายของมหาวิทยาลัยและกฎหมายที่เกี่ยวข้อง (BR-PRV-01)
- CON-IDN-01 การยืนยันตัวตนต้องทำผ่านบัตรนักศึกษาหรือ QR Code เท่านั้น (BR-IDN-01)
- CON-ELG-01 ผู้เข้าใช้บริการต้องเป็นนักศึกษา บุคลากร หรือผู้ที่ได้รับอนุญาตจากมหาวิทยาลัยหรือห้องสมุด และสิทธิ์ควรตรวจสอบจากข้อมูลสมาชิกหรือฐานข้อมูลที่ห้องสมุดกำหนด (BR-ELG-01)
- CON-SEC-01 ทุกการเชื่อมต่อต้องใช้ HTTPS (NFR-SEC-03, system-wide)

## Requirements
- FR-ACC-01 ระบบต้องอ่านข้อมูลจาก QR Code หรือบัตรนักศึกษา และตรวจสอบกับระบบบัตรนักศึกษาก่อนเข้าใช้บริการ  <- UC-01 ขั้น 1-3
- FR-ACC-02 ระบบต้องตรวจสอบสิทธิ์การเข้าใช้บริการของผู้แสดงบัตร/QR Code ตาม BR-ELG-01 และข้อมูลสมาชิกหรือฐานข้อมูลที่ห้องสมุดกำหนด <- UC-01 ขั้น 4
- FR-ACC-03 เมื่อยืนยันสิทธิ์สำเร็จ ระบบต้องบันทึกข้อมูลการเข้าใช้บริการ และปรับสถานะการเข้าใช้บริการแบบ Real-time <- UC-01 ขั้น 5-7
- FR-ACC-04 เมื่อระบบไม่สามารถอ่าน QR Code หรือบัตรนักศึกษาได้ ระบบต้องแจ้งให้สแกนใหม่โดยไม่บันทึกการเข้าใช้บริการ และต้องแยกสถานะเป็น "ไม่สามารถอ่านข้อมูล" <- UC-01 alt 2a
- FR-ACC-05 เมื่ออ่านข้อมูลได้แต่ไม่พบข้อมูลนักศึกษา หรือไม่มีสิทธิ์เข้าใช้บริการ หรือไม่สามารถตรวจสอบสิทธิ์ได้ ระบบต้องแจ้งเตือนและไม่อนุญาตให้เข้า และต้องแยกสถานะตามสาเหตุ ได้แก่ "ไม่พบข้อมูล" หรือ "ไม่มีสิทธิ์" หรือ "ไม่สามารถตรวจสอบสิทธิ์ได้" <- UC-01 exception 3a, 4a
- FR-ACC-06 เมื่ออ่านข้อมูลได้แต่ไม่พบข้อมูลในระบบ เจ้าหน้าที่ที่มีสิทธิ์สามารถตรวจสอบและยืนยันตัวตนด้วยมือได้ และระบบต้องบันทึกการดำเนินการไว้ใน Audit Log <- UC-01 exception 3a

## Quality Requirements
- NFR-PRF-01 ระบบต้องรองรับผู้ใช้งานพร้อมกันได้อย่างน้อย 500 คน
- NFR-PRF-02 การยืนยันตัวตนต้องเสร็จภายใน 2 วินาที และการอัปเดตจำนวนผู้ใช้บริการต้องเสร็จภายใน 2 วินาที หลังจากการเข้า/ออกได้รับการยืนยัน โดยรองรับผู้ใช้งานพร้อมกันอย่างน้อย 500 คน
- NFR-QAL-01 ระบบต้องมีความถูกต้องและแม่นยำในการตรวจสอบ QR Code
- NFR-SEC-01 ระบบต้องมีการรักษาความปลอดภัยของข้อมูลส่วนบุคคลของนักศึกษา

## Acceptance Criteria
- [ ] AC-ACC-01 (FR-ACC-01, FR-ACC-03)
      Given นักศึกษามีบัตรนักศึกษาที่ถูกต้องและมีสิทธิ์เข้าใช้บริการ
      When  นักศึกษาสแกน QR Code ที่เครื่องอ่าน
      Then  ระบบยืนยันตัวตนสำเร็จ อนุญาตให้เข้าใช้ห้องสมุด และบันทึกข้อมูลการเข้าใช้บริการ
- [ ] AC-ACC-02 (FR-ACC-05)
      Given นักศึกษาไม่มีสิทธิ์เข้าใช้บริการ
      When  นักศึกษาพยายามสแกนบัตรเพื่อเข้าห้องสมุด
      Then  ระบบแจ้งเตือนและไม่อนุญาตให้เข้า
- [ ] AC-ACC-03 (FR-ACC-04)
      Given เครื่องอ่านไม่สามารถอ่าน QR Code ได้
      When  นักศึกษาสแกนบัตร
      Then  ระบบให้สแกนใหม่ และไม่มีการบันทึกการเข้าใช้บริการเกิดขึ้น
- [ ] AC-ACC-04 (NFR-PRF-01)
      Given ผู้ใช้งานพร้อมกัน 500 คน
      When  แต่ละคนสแกนเข้าใช้บริการ
      Then  ระบบยังคงให้บริการได้โดยไม่ล่ม

## Assumptions & Open Questions
- ASM-01 ระบบบัตรนักศึกษา (UC-02) เป็นระบบภายนอกที่มี API ให้เรียกตรวจสอบสถานะได้แบบ synchronous
- ASM-02 "สถานะการเข้าใช้บริการแบบ Real-time" หมายถึงจำนวนผู้ใช้บริการปัจจุบันในอาคาร
- ASM-03 เมื่อระบบไม่สามารถตรวจสอบสิทธิ์ได้ ระบบจะไม่อนุญาตให้เข้าและแจ้งให้ผู้ใช้ลองใหม่หรือติดต่อเจ้าหน้าที่
- ASM-04 หากผู้ใช้อยู่ภายในห้องสมุด การสแกนซ้ำจะถูกปฏิเสธหรือไม่นับเป็นการเข้าใหม่
- ASM-05 หากอ่านข้อมูลได้แต่ไม่พบข้อมูลในระบบ เจ้าหน้าที่ที่มีสิทธิ์สามารถตรวจสอบและยืนยันตัวตนด้วยมือได้ และการดำเนินการนี้ต้องบันทึกใน Audit Log
- ASM-06 การยืนยันตัวตนและการอัปเดตจำนวนผู้ใช้บริการต้องเสร็จภายใน 2 วินาที หลังจากการเข้า/ออกได้รับการยืนยัน และต้องรองรับผู้ใช้งานพร้อมกันอย่างน้อย 500 คน
