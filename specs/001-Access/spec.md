# Feature: เข้าใช้บริการห้องสมุด (Library Access)
Spec ID: SPEC-LIB-001 | Source: SRS (NFR-PERF-01, NFR-SEC-01/02, NFR-USE-01, NFR-AVL-01) | Use case: UC-01
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-09

## Goal
นักศึกษาที่มีบัตรนักศึกษาหรือ QR Code ยืนยันตัวตนและสิทธิ์การเข้าใช้บริการห้องสมุดได้อย่างรวดเร็ว
ปลอดภัย และระบบบันทึกการเข้าใช้บริการทุกครั้งเพื่อการตรวจสอบย้อนหลัง

## Scope
### In scope
- อ่านข้อมูลจาก QR Code หรือบัตรนักศึกษา
- ตรวจสอบข้อมูลกับระบบบัตรนักศึกษา และตรวจสอบสิทธิ์การเข้าใช้บริการ
- แสดงผลการยืนยันสิทธิ์ และบันทึกข้อมูลการเข้าใช้บริการ (log เข้า-ออก)
### Out of scope
- การออกบัตรนักศึกษาหรือลงทะเบียน QR Code ใหม่
- การยืมคืนทรัพยากรห้องสมุด (แยกเป็น use case อื่น)
- การจัดการสิทธิ์การเข้าใช้บริการ (กำหนด/เพิกถอนสิทธิ์) ถือเป็น precondition ของฟีเจอร์นี้

## Constraints
- IF-STD-01 ระบบต้องเชื่อมต่อกับระบบบัตรนักศึกษาเพื่อตรวจสอบข้อมูลตัวตนของนักศึกษา
- DOM-SEC-01 ข้อมูลนักศึกษาต้องเข้ารหัสขณะรับส่งข้อมูลระหว่างอุปกรณ์สแกนกับระบบ
- DOม-AVL-01 ระบบต้องพร้อมใช้งานตลอดช่วงเวลาทำการของห้องสมุด
- CON-TECH-01 อุปกรณ์อ่าน QR Code / บัตรนักศึกษา ต้องรองรับการตรวจสอบสิทธิ์แบบ real-time

## Requirements
- FR-LIB-01 ระบบต้องอ่านข้อมูลจาก QR Code หรือบัตรนักศึกษา และตรวจสอบข้อมูลกับระบบบัตรนักศึกษา
  <- UC-01 ขั้นที่ 2-3
- FR-LIB-02 ระบบต้องตรวจสอบสิทธิ์การเข้าใช้บริการของนักศึกษาก่อนอนุญาตให้เข้าห้องสมุด
  <- UC-01 ขั้นที่ 4
- FR-LIB-03 เมื่อยืนยันสิทธิ์สำเร็จ ระบบต้องแสดงผลการยืนยัน บันทึกข้อมูลการเข้าใช้บริการ
  และอนุญาตให้นักศึกษาเข้าห้องสมุด                                    <- UC-01 ขั้นที่ 5-7
- FR-LIB-04 เมื่อระบบไม่สามารถอ่าน QR Code หรือบัตรนักศึกษาได้ ระบบต้องแจ้งเตือน
  และให้นักศึกษาสแกนหรือแสดงบัตรใหม่                                  <- UC-01 alternative 2a
- FR-LIB-05 เมื่อไม่พบข้อมูลนักศึกษาในระบบ ระบบต้องแจ้งว่าไม่สามารถยืนยันตัวตนได้
  และไม่อนุญาตให้เข้าใช้บริการ                                        <- UC-01 alternative 3a
- FR-LIB-06 เมื่อนักศึกษาไม่มีสิทธิ์เข้าใช้บริการ ระบบต้องแจ้งเตือนและไม่อนุญาตให้เข้า
  <- UC-01 alternative 4a
- FR-LIB-07 เมื่อระบบไม่สามารถเชื่อมต่อกับระบบบัตรนักศึกษาได้ ระบบต้องแจ้งเตือนว่าไม่สามารถ
  ตรวจสอบข้อมูลได้ และไม่อนุญาตให้เข้าใช้บริการ                        <- UC-01 exception 3a
- FR-LIB-08 เมื่อระบบไม่สามารถบันทึกข้อมูลการเข้าใช้บริการได้ ระบบต้องแจ้งข้อผิดพลาด
  และไม่อนุญาตให้เข้าใช้บริการ                                        <- UC-01 exception 6a

## Quality Requirements
- NFR-PERF-01 ระบบต้องอ่าน QR Code หรือบัตรนักศึกษาและแสดงผลภายใน 2 วินาที
- NFR-SEC-01 ข้อมูลนักศึกษาต้องถูกเข้ารหัสขณะรับส่งข้อมูล
- NFR-SEC-02 ระบบต้องตรวจสอบสิทธิ์ของนักศึกษาก่อนอนุญาตให้เข้าใช้บริการ
- NFR-USE-01 การสแกน QR Code หรือใช้บัตรนักศึกษาต้องทำได้ง่ายและสะดวก
- NFR-AVL-01 ระบบต้องพร้อมใช้งานสำหรับการเข้าใช้บริการห้องสมุดในช่วงเวลาทำการ

## Acceptance Criteria
- [ ] AC-LIB-01 (FR-LIB-01, NFR-PERF-01)
      Given นักศึกษามี QR Code หรือบัตรนักศึกษา
      When  นักศึกษาสแกน QR Code หรือใช้บัตร
      Then  ระบบอ่านและตรวจสอบข้อมูลตัวตนได้ภายใน 2 วินาที
- [ ] AC-LIB-02 (FR-LIB-02, FR-LIB-03)
      Given นักศึกษามีสิทธิ์เข้าใช้บริการ
      When  ระบบตรวจสอบสิทธิ์สำเร็จ
      Then  ระบบอนุญาตให้เข้าใช้ห้องสมุดและบันทึกข้อมูลการเข้าใช้บริการ
- [ ] AC-LIB-03 (FR-LIB-06)
      Given นักศึกษาไม่มีสิทธิ์เข้าใช้บริการ
      When  ระบบตรวจสอบสิทธิ์
      Then  ระบบไม่อนุญาตให้เข้าใช้บริการและแสดงข้อความแจ้งเตือน
- [ ] AC-LIB-04 (FR-LIB-04)
      Given ระบบไม่สามารถอ่าน QR Code หรือบัตรนักศึกษาได้
      When  นักศึกษาทำการสแกนหรือแสดงบัตร
      Then  ระบบแจ้งเตือนและให้นักศึกษาลองใหม่
- [ ] AC-LIB-05 (FR-LIB-05, FR-LIB-07)
      Given ไม่พบข้อมูลนักศึกษา หรือระบบเชื่อมต่อกับระบบบัตรนักศึกษาไม่ได้
      When  ระบบตรวจสอบข้อมูลตัวตน
      Then  ระบบแจ้งว่าไม่สามารถยืนยันตัวตนได้และไม่อนุญาตให้เข้าใช้บริการ
- [ ] AC-LIB-06 (FR-LIB-08)
      Given ระบบไม่สามารถบันทึกข้อมูลการเข้าใช้บริการได้
      When  การยืนยันสิทธิ์เสร็จสิ้น
      Then  ระบบแจ้งข้อผิดพลาดและไม่อนุญาตให้เข้าใช้บริการ

## Assumptions & Open Questions
- ASM-01 ระบบบัตรนักศึกษาเป็นระบบภายนอกที่มีอยู่แล้ว และเปิด interface ให้ตรวจสอบข้อมูลแบบ real-time
- ASM-02 สิทธิ์การเข้าใช้บริการ (เช่น ค่าปรับค้างชำระ, สถานะนักศึกษา) ถูกกำหนดไว้ล่วงหน้าจากระบบอื่น
- Q-01 กรณีเชื่อมต่อระบบบัตรนักศึกษาไม่ได้ (exception 3a) ควรมี fallback ให้เจ้าหน้าที่ยืนยันตัวตนด้วยมือหรือไม่?
- Q-02 ต้องเก็บ log การเข้าใช้บริการไว้นานเท่าใด และมีข้อกำหนด PDPA เกี่ยวข้องหรือไม่?
